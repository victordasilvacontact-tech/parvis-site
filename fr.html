La partie multi-organisations de votre SaaS, déjà construite et testée.

Parvis est un kit en code source sur Angular, Spring Boot et Keycloak. Connexion, organisations, invitations, rôles et journal d'audit sont faits : votre première semaine sert votre propre produit.

Pourquoi ce kit

Tout produit B2B a besoin de connexion, d'organisations, de membres, de rôles et d'une trace de qui a fait quoi avant d'avoir une seule fonctionnalité. C'est des semaines de travail.

Le plus dur est de garder les données d'un client hors de portée d'un autre. C'est aussi ce qu'on rate le plus facilement sans s'en apercevoir. Parvis le fait une fois, avec des tests qui le prouvent.

Contenu

Organisations et invitations
L'inscription crée une organisation et fait de son créateur le Propriétaire. Les autres personnes entrent sur invitation.
Rôles modifiables
Chaque organisation compose ses rôles sur un écran. Elle ne peut pas perdre son dernier Propriétaire ni accorder une permission que son éditeur n'a pas.
Journal d'audit
Un par organisation, avec un écran pour le lire et le filtrer.
Keycloak, piloté depuis l'application
Membres, invitations et réglages se gèrent dans vos écrans : personne n'ouvre la console Keycloak.
Sessions sans jeton dans le navigateur
OIDC côté serveur avec un cookie HttpOnly. L'API accepte aussi un jeton Bearer.
Écran opérateur
Lister et suspendre des organisations.
Français et anglais, clair et sombre
Changement de langue sans rechargement. Les couleurs viennent d'un fichier de thème.
Tests et CI
docker compose up le lance. Un fichier Compose séparé sert la production. GitHub Actions couvre le backend, le frontend, le bout en bout et les images.
De la place pour votre code
Votre dossier de migrations avec des plages de versions réservées, un moyen d'ajouter des permissions, et des tests d'architecture qui gardent vos ajouts sur le bon chemin.
Documentation en français et en anglais
Une page par fonctionnalité, chacune avec un exemple.

Écrans

Ce que le build vérifie

Isolation des donnéesDes tests couvrent JPA, le SQL natif et les tables que vous ajoutez. RlsCoverageIT fait échouer le build sur toute table sans politique.
PermissionsChaque route déclare la permission requise. Un test d'architecture fait échouer le build si ce n'est pas le cas.
Réglages de productionLe Compose de production refuse les secrets publics change-me-* et les realms en HTTP simple.
Nombre de tests672 en backend, environ 290 en frontend et 27 de bout en bout (Playwright).
Revue de sécuritéAnalyse semgrep, avis de sécurité des dépendances vérifiés et revue manuelle. Chaque constat a été corrigé avec un test.

Technologies

Java 25, Spring Boot 4.1, Spring Security 7, Hibernate 7, PostgreSQL 18, Flyway, Angular 22, Keycloak 26.8, nginx, Playwright, Docker Compose et GitHub Actions. Il vous faut Java 25 et Node 24 LTS.

Pour lancer la démo :

cp .env.example .env
docker compose --profile demo up -d --build --wait

Puis ouvrez http://localhost:4200.

Est-ce pour vous

Il convient aux freelances, petites agences et éditeurs de SaaS qui construisent un produit B2B multi-organisations sur cette pile exacte.

Non inclus : abonnements et paiements, préréglages SAML, plusieurs organisations par utilisateur, manifestes Kubernetes, registre d'images publié. Si vous voulez un générateur de code ou un autre frontend, JHipster est gratuit et un bon choix.
